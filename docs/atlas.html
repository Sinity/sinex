Sinex is a local-first, single-operator event platform: one Rust workspace, one daemon (sinexd), one CLI (sinexctl), one automation plane (xtask), NATS JetStream transport, PostgreSQL (TimescaleDB + pgvector) canonical store, deployed on one NixOS host. This atlas is the single orientation page: why the system exists, how the architecture actually works, what it captures and derives today, how it is deployed, and where the live frontier is. Every load-bearing number carries its measurement query; doctrine summaries cite the owning committed doc. The work-ahead section is a dated snapshot of the Beads graph, which remains the only live backlog authority.

Why Sinex exists

Sinex creates a structured, queryable record of one person's digital activity — filesystem, terminal, desktop, browser, system, documents, exports — as an append-only event log behind a single query surface. Its purpose is context recovery: reconstructing what was happening before an interruption, correlating activity across sources, and answering cross-source temporal questions that no individual tool can. It is built for an operator who needs capture to be automatic and invisible, query to be structured and precise, and engagement to be entirely optional:

A feature that requires energy to use fails when it matters most. north-star doctrine, retained from the target-vision corpus

Five identity principles

  • Raw source material outranks any interpretation. Source bytes are ground truth; events can be re-derived from them, never vice versa (raw.source_material_registry + anchor pointers).
  • Interpretation is replayable and replaceable. Fixes archive old events and re-read the material through the normal pipeline with current rules.
  • Source interpreters are mechanical translators, not intelligence. Parsers translate bytes to typed intents; higher-order context comes from joins and derivation, never hidden enrichment at capture time.
  • Intelligence is additive and provenance-tracked. Automata emit synthesis events with explicit parents, model, and semantics version.
  • One coherent query surface. No per-source silos; everything is queryable through the same engine.

What the system refuses

Sinex is a witness, not a manager: no hidden AI mutations of the raw record, no plaintext-notes-as-ontology, no streaks/scores/gamification, no push prescriptions. Derived observations are emitted to be queried, never to nudge. The system must remain correct when ignored for a month.

The long-form narrative ("why" essay, research corroboration, ecosystem framing) lives in sinex-target-vision/report/vision.md, the one chapter of that corpus kept after this atlas retired the rest.

Architecture

Authority: docs/architecture.md (deep dive) and CLAUDE.md (dense always-loaded summary). This section is the map, not a replacement.

Provenance: the one load-bearing idea

Every event has exactly one provenance, enforced at four levels (builder typestate, serde wire format, DB XOR CHECK, NonEmptyVec):

KindFieldsMeaningReplay
Materialsource_material_id set "I interpreted this byte range of this registered source material" re-read the material
Derivedsource_event_ids set "I derived this from these parent events" re-run the automaton on the parents

Three clocks ride every event — and they are supposed to differ for imports; falsifying any of them is a doctrine tripwire:

ClockMeaningAcross replay
ts_origwhen it happened in the world (quality-ranked via raw.temporal_ledger)stable
ts_coidedwhen sinex minted this interpretation (generated from the UUIDv7 id)new
ts_persistedrow write timenew

Identity: the event id is interpretation identity — replay mints new ids through the normal pipeline. Occurrence identity is the (source_material_id, anchor_byte) columns, stable across replay and never the PK. Occurrence dedup, where it exists, is the admission-time equivalence_key check (fail-open, three distinct idempotence regimes — see architecture.md §dedup contract). Replay is non-idempotent by design: archive cascade → scope invalidation → re-read → fresh events with new ids and the same occurrence coordinates.

Pipeline (source → query)

Failure routing: JSON/schema failures → DLQ; FK-not-ready → NAK + delay; poison rows in a COPY batch → bisect and isolate; terminal delivery count → DLQ. Two storage lanes (core.events activity, reflection.events self-observation) keep self-observation out of activity surfaces. Drift-proof anchors: stream/consumer shapes in event_engine/jetstream_consumer/bootstrap.rs + nixos/modules/nats.nix.

Schema evolution is declarative convergence (sinex-schema apply), not migrations; drift the engine cannot reconcile surfaces through xtask schema strict-diff. sqlx compiles against the live dev database only — no offline cache, by doctrine.

Type-enforcement ladder

Every invariant gets the strongest affordable level; a correctness invariant may never stay at convention-only: 1 compile-time (typestate, Id<T>, newtypes) · 2 lint / forbidden-pattern gates · 3 DB constraints · 4 runtime boundary validation · 5 startup/lazy contract checks · 6 convention (danger zone, documented). The full ladder with examples is architecture.md §Type Enforcement Hierarchy.

Storage / authority split

Raw material and raw events are the durable witness layer; projection rows are rebuildable read models; candidate claims carry evidence; operator judgments are explicit promotion decisions; presentation packs are consumers, never authorities. Canonical derived events and accepted claims are the only default inputs to further derivation. A derivation that cannot name which layer it writes is not ready to implement.

What is real beyond the registry

  • Derivation control plane measured — every registry entry carries static DerivationOutputDeclarations validated against runtime enforcement (registry.rs doc comment; epic sinex-0vx closed).
  • Semantic lanes / epochs, LLM routing, curation — live read surfaces exist end-to-end: sinexctl semantic and MCP tools (sinex_semantic_lanes/epochs/lane_diffs, sinex_llm_prompts/route_explain/budget_report, sinex_curation_proposals). The old vision-era claim "LLM integration: zero" is dead; what remains open is activation (embedding worker sinex-5v6, cost fuse sinex-2k2, budget automaton sinex-a4w.5).
  • Proposal / judgment / finalizer — the adjudication plane landed (sinex-0vx.5 finalizer registry closed; interactive judgment seat is sinex-7z0.4, open P1).
  • Knowledge graph — schema + repositories exist; population waits on the entity-family consumer substrate; person-entity design is sinex-a4w.3.13.

Deployment reality, not aspiration

  • Deployment wiring is the bottleneck, not contracts: a generic scheduled static-import glue (mkStaticImportGlue, nixos/modules/sources.nix) landed with git + raindrop as the first defaults; generalizing it to the remaining "dark" contracts (~11 without runtime bindings derived from the sinex-stm 2026-07-06 census note) is open work (sinex-stm P2, live-host proof sinex-2bk P1).
  • Portfolio governance is explicit: sinex-5j8 (operator keep/prune/freeze decision per capture domain), sinex-rkv (capture breadth epic: GitHub/CI, nix generations, browser content, calendar, mobile bridges, physiological raw data, satellite hosts), sinex-44q/sinex-k4c (Lynchpin source subsumption with a promotion ledger), sinex-xv1 (media runtime tier), sinex-di7 (email runtime tier).
  • Known untracked-until-recently gaps were beaded from the 2026-08-02 target-vision triage: live browser capture client (sinex-vision-browser-live-client) and the keylog source decision (sinex-vision-scribetap-keylog-source).

Live state (dated)

measured 2026-08-02: sinexd, postgresql, and nats are all inactive on the deployment host. This is deliberate, not an outage: the operator-ratified fresh-rebuild campaign (bead sinex-poma, the only P0) is wiping and re-importing the polluted dataset after landing bake-in fixes, an explicit one-time override of the "state is durable, never wipe" doctrine with a full snapshot taken first. Until the rebuild completes, runtime-status surfaces (gateway, MCP status tools) report degraded.

Trust boundary summary: JSON-RPC + SSE behind TLS with token-suffix RBAC (:readonly < :write < :admin; rotation, no revocation); native-messaging surface with per-extension capability ACLs; MCP read tools redact raw payload samples by default. Privacy/redaction is a presentation feature by doctrine — source access and deployment isolation own confidentiality.

Known open correctness seams

Verified, deliberately sequenced (not fix-ad-hoc): emission is an in-memory handoff until NATS publish, so source cursors and automaton checkpoints can durably advance before outputs are durable — the crash-loss window the sinex-r6d family (r6d.4, vxu, r6d.7) closes with one shared durable-emission receipt. Also: the recovery spool caps preserved lines; health defaults to healthy when a reporter is missing. Source: CLAUDE.md §Known open correctness seams.
