# Credential presentation

All registered native JSON-RPC replies, including failures and captured metadata, pass through whole-response presentation admission before any JSON body bytes are released. The actual daemon and CLI share that path. Query, show and retained trace mask the fixed `credential-output-v1` catalog independently of configured optional rules. Query rows and show/trace rows carry `secret: true` when fixed-catalog masking changed their presented text, and `false` otherwise. This flag describes the current presentation; it does not index raw credentials or prove absence in retained bytes. The native protocol has no reveal operation. MCP, exports and general read models remain unavailable.

Each JSON string is one logical value. Arrays, nested captured values, strings decoded from canonical retained JSON and captured host metadata are covered. Buffer boundaries do not end recognition. Different fields are never concatenated. The shared bounded streaming engine is `credential-output`; the independent 132-case fragmented corpus remains with its owner. An undecided recognition region beyond the engine bound returns a typed refusal. The adapter additionally limits each masked string and the encoded response to 128 MiB; the existing query page remains at most 100 rows. It admits the complete page before emitting its body, preserving the current response shape and retained-page semantics.

Captured member names are checked and refused if masking would change them. Opaque identities, native IDs, session selectors, query echoes, cursors, hashes and other control metadata are preserved exactly or refused. Unclassified non-payload metadata follows the same refusal rule, while captured payload/record values and named descriptive fields can be masked. This prevents ambiguous key collisions or selectors that no longer name their original objects. Credential-bearing requests are refused before execution; a safe request ID is retained in the error, and an unsafe ID becomes null rather than being rewritten. No member is silently omitted.

The floor changes presentation only. Raw canonical rows, event payloads, record hashes, retained material hashes and parser provenance retain their existing semantics. Operator rules still run at admission and on the existing presentation path; raw keys and identities are validated before those presentation rules, and the fixed floor renders the final response once so a replacement cannot inject a credential-shaped string. Archive versions, source interpretations and generation schemas do not change.

Database read deadlines and disconnect cancellation retain their existing guarantees. Synchronous bounded presentation is not universally CPU-preemptible: the database timeout does not promise to interrupt every recognition or encoding instruction. Whole-response refusal prevents partial successful documents.

Qualification: `agentctl job start WORKTREE credential_output_acceptance --workspace WORKTREE` runs the packaged Atuin path with empty optional rules, fixed-family/context cases in one long native string, metadata, query/show/trace, request identity/key refusal, native identity page refusal, provider deletion and restart, and retained payload/hash/provenance equality. The adapter's Rust tests exercise nested captured JSON and captured-key refusal through the actual response encoder. Atuin's registered source emits fixed member names, so it cannot supply arbitrary captured keys; these encoder controls do not claim an additional source is registered. Existing `atuin_package_acceptance` separately retains configured-rule behavior.

The current dependency is an explicit temporary exact owner Git commit for local qualification. Integration must publish the independently reviewed immutable credential crate tag and replace the temporary URL and Nix builtin fetch permission with that remote tag and its verified output hash. No vendor or path fallback is supported.
