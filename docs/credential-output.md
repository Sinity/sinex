# Credential presentation

All registered native JSON-RPC replies, including failures and captured metadata, pass through whole-response presentation admission before any JSON body bytes are released. The actual daemon, CLI and registered MCP read tools share that path. Query, show and retained trace mask the fixed `credential-output-v1` catalog independently of configured optional rules. Query rows and show/trace rows carry `secret: true` when fixed-catalog masking changed their presented text, and `false` otherwise. This flag describes the current presentation; it does not index raw credentials or prove absence in retained bytes. The native protocol has no reveal operation. Indexed snippets retain the complete logical string through this floor before trimming; changed text loses its old highlight ranges. Exports and the broader read-model lifecycle remain unavailable.

Each JSON string is one logical value. Arrays, nested captured values, strings decoded from canonical retained JSON and captured host metadata are covered. Buffer boundaries do not end recognition. Different fields are never concatenated. The shared bounded streaming engine is `credential-output`; the independent 132-case fragmented corpus remains with its owner. An undecided recognition region beyond the engine bound returns a typed refusal. The adapter additionally limits each masked string and the encoded response to 128 MiB; the existing query page remains at most 100 rows. It admits the complete page before emitting its body, preserving the current response shape and retained-page semantics.

Captured member names are checked and refused if masking would change them. Opaque identities, native IDs, session selectors, query echoes, cursors, hashes and other control metadata are preserved exactly or refused. Unclassified non-payload metadata follows the same refusal rule, while captured payload/record values and named descriptive fields can be masked. This prevents ambiguous key collisions or selectors that no longer name their original objects. Request credential screening only inspects immutable strings and keys; method validation owns parameter shapes, including malformed scalar, array and null inputs. Response decoration requires row objects and refuses malformed row shapes before success. Credential-bearing requests are refused before execution; a safe request ID is retained in the error, and an unsafe ID becomes null rather than being rewritten. No member is silently omitted.

The floor changes presentation only. Raw canonical rows, event payloads, record hashes, retained material hashes and parser provenance retain their existing semantics. Optional operator rules run once when admitting an interpretation, including replay from retained original evidence. Query, search and show preserve those stored values without applying current optional rules again. Native retained raw-record reads use the bounded attributed-then-additional-current rule sequence defined in the [Atuin contract](rewrite/atuin.md). The same attributed tuple is not reapplied from current configuration. This protected raw projection can differ from stored interpretations, including when material was acquired with no optional rules; it does not reinterpret ordinary stored values. The fixed floor then admits the final response, including identity and key refusal, so an optional replacement cannot inject a credential-shaped string. Archive versions, source interpretations and generation schemas do not change.

Database read deadlines and disconnect cancellation retain their existing guarantees. Synchronous bounded presentation is not universally CPU-preemptible: the database timeout does not promise to interrupt every recognition or encoding instruction. Whole-response refusal prevents partial successful documents.

Qualification: `agentctl job start WORKTREE credential_output_acceptance --workspace WORKTREE` runs the packaged Atuin path with empty optional rules, fixed-family/context cases in one long native string, metadata, query/show/trace, request identity/key refusal, native identity page refusal, provider deletion and restart, and retained payload/hash/provenance equality. The adapter's Rust tests exercise nested captured JSON and captured-key refusal through the actual response encoder. Atuin's registered source emits fixed member names, so it cannot supply arbitrary captured keys; these encoder controls do not claim an additional source is registered. Existing `atuin_package_acceptance` separately retains configured-rule behavior.

The dependency is the owner's immutable `credential-output-v0.1.0` tag in `https://github.com/Sinity/polylogue`, locked to release commit `beba1cbd21ee0c251819a2ff38282c4875368cca`. Nix verifies the owner source through an explicit output hash. The tag identifies the independently packageable crate and its corpus; downstream packaged-client qualification remains separate. No vendor copy, path dependency or builtin-fetch fallback is supported.
