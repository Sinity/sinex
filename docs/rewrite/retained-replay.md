# Retained Atuin replay

The foundation reparses one explicitly selected closed Atuin logical-row material through its existing parser and private writer. `replay.plan`, `replay.start`, `replay.status` and `replay.cancel` are the implemented API methods. The CLI accepts only `materials where id = UUID`, optionally quoting the UUID. A selection may contain at most 4,096 retained records. Other selections, parser overrides, other sources, automata and a general replay engine remain unavailable.

Enable the fixed operator profile with a separate credential file:

```toml
replay_token_file = "/absolute/path/replay-operator-token"
```

The existing `token_file` authorizes reads, including replay planning and status. Mutation requires the explicitly configured replay credential, which must differ from the read credential. The server assigns the stable principal `foundation.operator`; it never derives identity from credential contents or accepts a caller-supplied principal. This is one explicit operator profile. Agent credentials, session authorship, the full three-token policy and library action records remain planned. Every request rechecks its bearer credential. Startup resumes pending operations only while that operator profile is enabled. `status` exposes `replay_authorized` and recent typed replay outcomes; disabling the profile leaves their committed progress intact.

```sh
sinexctl --endpoint http://127.0.0.1:41037/rpc --token-file /absolute/read-token replay 'materials where id = MATERIAL_UUID' --dry-run --json
sinexctl --endpoint http://127.0.0.1:41037/rpc --token-file /absolute/replay-operator-token replay 'materials where id = MATERIAL_UUID' --action-id ACTION_UUID --json
sinexctl --endpoint http://127.0.0.1:41037/rpc --token-file /absolute/read-token replay-status OPERATION_UUID --json
sinexctl --endpoint http://127.0.0.1:41037/rpc --token-file /absolute/replay-operator-token replay-cancel OPERATION_UUID --json
```

A direct replay needs no preview. If `--action-id` is omitted, the CLI mints an action identity and prints it on stderr before submitting the request. Keep that identity to recover a lost reply. The CLI waits for the admitted operation's terminal outcome; it does not schedule the chunks. A disconnected client neither cancels the operation nor stops its remaining work. The existing writer runs bounded chunks between queued commands and resumes unfinished operations from their committed progress after restart. Explicit cancellation settles the current transaction before stopping between chunks. It preserves earlier replacements and has no undo. A cancelled action stays cancelled on retry; a new replay is a new action.

The dry run reads retained evidence and reports selected-record and chunk counts without writing an operation. Its `basis` binds exact retained ranges, their selected interpretations (including absence), the parser executable digest and current configured privacy rules. Pass it as `--basis BASIS` (API `expected_basis`) to require that preview's basis. A new action with a changed basis records a no-effect refusal. Without a supplied basis, direct run resolves its own current selection. Every admitted request retains its resolved parser executable and privacy-policy interpretation basis. Continuation rechecks current authorization and rules, then refuses unsupported basis drift while preserving earlier committed ranges. It never finishes one operation with a mixture of parser artifacts or pins old privacy rules to bypass current restrictions. Planning and execution counts agree when the supplied basis is accepted; there is no persistent snapshot. Material and interpretation changes after admission can refuse a later chunk while preserving earlier committed ranges.

An action is unique under its authenticated principal. It binds `sinex.replay.request.v1`, the normalized material selection and optional expected basis. Matching retries recover the existing operation before consulting stale material preconditions; different content conflicts. A recorded no-effect refusal remains that refusal after the backing is repaired. The operation row owns its immutable selection and typed progress. Its versioned request and outcome references select exact plain retained records in the existing material/blob registry. Retry and status read, hash-verify and validate those records; missing, corrupt or unsupported authority refuses comparison and permits no new event effects. The scope retains selected ranges and a completed preflight marker, not a second request copy. Each committed step binds a retained `sinex.replay.effects.v1` manifest through `core.operation_effects`. Prepared files acquire no effect authority until their binding commits. This implements the replay subset of current specification storage §3.7.1, not the full action/library reconstruction or undo protocol. The physical references are whole-material UUIDs under their named formats; arbitrary range and sealed references remain unavailable.

Selection enumerates retained rows, including valid rows a historical interpretation omitted. It does not enumerate only current event IDs. Each chunk processes at most 64 records and 1 MiB of retained row data. Parsing and integrity checks happen before replacement; a new operation validates its entire bounded selection before its first replacement, and each chunk rechecks its selected basis and backing. Missing, corrupt or malformed evidence cannot turn into successful zero or archive the prior answers. A source key currently interpreted from another material is refused rather than silently replacing that material's newer reading. Physical SQLite reconstruction and provider reacquisition are never used.

The replacement transaction archives each selected old reading that exists, admits the current parser's readings, updates live coordinates/equivalence and commit-log entries, binds the exact step effects and outcome, and advances the operation's range progress together. Equal content is deliberately reminted. New interpretations cite the same exact retained material/range and preserve ordinal, event type, equivalence, acquisition hash and intrinsic time where unchanged. Their IDs, processing time, run/artifact attribution and `created_by_operation` change. `show` and raw query rows expose the operation and run; archived readings remain inspectable through `show` and `trace`.

Progress (`processed`, `next_anchor`, `steps`) is independent of actual `archived` and `admitted` counts. A restored omission increases admissions without inventing an archive. Atuin source-removed rows are admitted as removed readings, matching normal acquisition; they stay absent from ordinary queries while their range advances. This parser emits one reading for each valid retained row. General zero-output parsers and derived invalidation remain unavailable. A malformed retained row refuses the selection instead of treating a parser error as a successful empty range.

Outcomes distinguish `recorded`, `running`, `completed`, `refused` and `cancelled`. `complete` is true only for completed replay. CLI replay waits for the terminal state; status on unfinished work and cancelled replay exit 5, refusal exits 4, invalid syntax exits 2, and complete replay exits 0. A transport error reports that no complete response arrived. It does not establish whether a commit happened: recover the same action or inspect its operation. After a commit, qualification-controller failure cannot relabel that committed step as a no-effect failure.

`retained_replay_acceptance` builds the Nix package and runs its actual daemon and CLI in the foundation harness's owned PostgreSQL state. Its independent 130-row fixture has 64 source-removed records, a controlled bad hostname reading and one deliberately omitted valid row. `--qualification-historical-atuin` admits that labelled historical fixture through the typed source path; it does not claim an actual predecessor binary produced it. The unchanged parser restores the correct hostname from retained bytes and restores the omitted row after the original provider is deleted. The acquisition source is disabled for this replay qualification; the separate provider-loss suite covers unavailable configured-source coverage. Expected visible count changes from 65 to 66; processed/admitted/archived totals are 130/130/129. This is a different fixture from Kestrel's source count 10-to-9 and its unimplemented fusion outputs.

The qualification control accepts `replay-staged-N` and `replay-committed-N`, for zero-based steps 0 through 63, through the existing explicit `--qualification-boundary` and `--qualification-socket` flags. It rendezvouses at the real replacement transaction before COMMIT or after COMMIT and before its reply. The suite observes two committed ranges, including an entirely removed range, before killing a later staged transaction. It also exercises a committed-but-unreplied step, restart with the operator profile disabled then restored, client death while the owner continues, explicit cancellation queued before boundary release, unavailable/corrupt/malformed evidence, durable refusals, stale previews and wrong request reuse. A runnable copy of the packaged ELF with an appended qualification marker supplies a real changed executable digest for the restart/basis refusal; the report labels that controlled artifact and retains its exact bytes and actual run identity. Missing/corrupt retained request and outcome records separately qualify comparison authority. Frames, PIDs, exact commands/exits, independent expectations, retained encoded bytes, actual before/after answers and operation/step bindings stay in its private report. This is process interruption evidence. Power loss, large-corpus fairness and the later full action, multisource fusion and M0/M1 gates remain unqualified. Indexed projection maintenance has its separate qualification below.

The older pinned foundation design remains its broader basis. This supported replay subset follows the current specification's derivation §5, storage §3.7.1, surfaces §4 and slice-01 refinements. Raw-event clients retain their separate supported scope. The [indexed retrieval subset](indexed-retrieval.md) now maintains canonical/search projections after replay; replay admission completion and projection readiness remain distinct, explicitly observable states.
