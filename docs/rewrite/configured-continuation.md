# Configured Atuin continuation qualification

The published collector already polls its configured Atuin database and submits retained logical rows to the normal writer. This scenario binds that existing route to a finite ongoing-use example, following the joint realization plan's M2a continuation outcome. It adds no source, query feature, writer or deployed service.

`configured_continuation` runs the existing foundation harness with an explicit immutable package pin:

```sh
agentctl job start --project /absolute/checkout --workspace /absolute/checkout configured_continuation -- --package-pin /absolute/qualification-pin.json
```

The pin must match the clean qualification checkout and retain the actual package build source, tree and binary hashes separately. Reusing an earlier package requires proving that its runtime/build inputs are unchanged. The operation never builds or chooses a development fallback. Other scenario selectors refuse. The harness owns PostgreSQL 18/Timescale, one SQLite producer, ordinary daemon/CLI and the actual `rmcp` child. No private or live source is accessed, and no model is run.

The authored workload starts with a completed empty database. One unchanged collector then acquires batches of 96, 160 and 128 rows at the same path, without selecting or importing each update. It observes two autonomous repeat passes. A fourth 128-row batch arrives while the daemon is stopped; a same-state restart catches up. The 512 source rows include 448 exact-project rows and 64 path-neighbor distractors, repeated identical command text with distinct occurrence keys, recorded failures, unknown ends/exits, and zero-exit pipeline/queued-submission examples. These are synthetic source records, not executed checks or evidence of their underlying results. This workload size is a qualification domain, not a product capacity limit.

Ordinary CLI and advertised MCP discovery/search recover the selected rows without supplied answer event IDs. The checker compares exact source identities and fields, project membership, snippets, cross-client row identity and retained parent coordinates. Selected citations come from actual returned rows, including a new row from every later batch and catch-up. It independently decompresses each addressed logical material and checks the actual span and all nine source fields against fixture facts. Restart preserves earlier cited interpretations. A final owned provider-path outage must report unavailable with retained rows and incomplete coverage, unlike the initial completed empty source. Earlier transaction interruption, provider-loss, exclusion/replay, schema and fusion qualifications remain separate; this scenario does not repeat or broaden them.

The private result retains producer-commit-to-query and restart-catchup timings, source-pass accounting, database/retained-store/filesystem growth, actual interventions, command exits, process logs and a readable report. Timings include both client traversals and the intervening acquisition/writer/derivation/projection work. Storage samples are not a single atomic physical snapshot. The maintenance watchdog detects unfinished work and retains its status/progress; it is not a throughput pass bar. Atuin currently rereads full snapshots, and shell reconciliation considers the eligible population. This finite case establishes neither daily scalability nor ordinary retrieval superiority, productivity benefit, complete capture, full slice/M0/M1 completion or installed acceptance.
