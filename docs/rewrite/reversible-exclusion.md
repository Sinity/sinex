# Reversible retained Atuin exclusion

This native subset excludes one retained `terminal.atuin-history` / `command.executed` occurrence through the existing writer. `delete.run` and `delete.undo` are the implemented API methods. A target is one raw interpretation UUID or `sinex:ev/UUID`, including an archived interpretation of that occurrence. Its stable equivalence key, not command text or the selected interpretation ID, determines what stays excluded. Two identical commands with different native Atuin IDs remain distinct occurrences. No material bytes or interpretation rows are deleted.

```toml
operator_token_file = "/absolute/operator-token"
```

This replaces the former replay-only credential configuration field; there is no compatibility alias. It enables the existing finite `foundation.operator` principal for replay and these two actions. `token_file` retains read authority and cannot mutate. The operator credential must differ from the read credential. Authentication is checked on every API attempt, including retries. No agent credential, automatic terminal/harness token routing, general role system or MCP write tool is implemented.

```sh
sinexctl --endpoint http://127.0.0.1:41037/rpc --token-file /absolute/operator-token delete RAW_REF --action-id ACTION_UUID --json
sinexctl --endpoint http://127.0.0.1:41037/rpc --token-file /absolute/operator-token delete --undo RAW_REF --action-id ANOTHER_ACTION_UUID --json
```

API parameters are the strict typed object `{ "ref": "sinex:ev/UUID", "action_id": "UUID", "expected_key": null }`. `expected_key`, also available as CLI `--expected-key`, is an optional exact occurrence-key precondition. Keys over 2,048 UTF-8 bytes are refused by this bounded subset. Canonical references refuse with their exact raw parent reference, without applying the action to that parent. Query-wide deletion, other sources, coordinate-only types, purge and excision are unavailable.

The exclusion transaction inserts `core.deleted_occurrences` with kind `exclude` and the originating operation, archives the current raw interpretation and its singleton canonical child, releases their live side-table keys, publishes their commit changes and records durable canonical dirty work. Existing read-model maintenance consumes the committed changes. Pending or failed projection maintenance cannot become a complete stale search. The archive remains available through `show` and retained `trace --bytes`.

Admission checks the listed stable key on every normal reading and retained replay. A changed provider row under the same key remains excluded. Suppressed source rows still acquire retained evidence, count toward `rows_read`, and are separately counted as `excluded`, rather than reported as ordinary duplicates. Excluded replay ranges commit processing progress with no admissions. The existing preview basis binds exclusion eligibility, so excluded-preview → undo → execution under that stale basis refuses; a new action with a fresh basis can proceed.

Undo removes only kind `exclude`. It refuses `purge` and `excise` and never unarchives an interpretation or reads the provider. With the provider stopped, the occurrence remains absent until an explicit retained replay admits a new interpretation. After undo a later normal source acquisition may also admit it. No hidden exclusion is inferred from archived history.

Both mutations use the same `core.operations_log` principal/action uniqueness as replay. Their retained versioned semantic requests, outcomes and exact effect records use the existing material/blob custody and subordinate `core.operation_effects` binding. Each action commits its operation, effect binding and database effects atomically. Prepared material alone selects no effects. Retry hash-verifies the retained request/outcome/effects before returning the original finalized result, even if later actions undid or replaced that result. Different target, method or expected key under the same action identity conflicts. A finalized no-op, absent-target result or refusal stays that original result on retry. Missing or corrupt comparison material permits no new effect.

A successful delete/undo response must decode as the supported typed outcome and match the requested action ID, method and normalized target, as well as an explicit expected key if supplied. A missing or mismatched required binding is indeterminate, even when the JSON-RPC response ID matches. The CLI prints a newly generated action identity before sending the request; retain it if the reply is lost. A disconnected client does not cancel queued writer work. An unavailable mutation reply or an incompatible response identity reports an indeterminate outcome and advises retrying the same identity; it cannot establish that no commit happened. If a committed outcome cannot pass credential presentation admission, the API returns `partial` with its action/operation identities and `retained_but_unpresentable`, rather than implying no effect. Qualification rendezvous `delete-staged` and `delete-committed` expose the real transaction boundary through the existing isolated controller mechanism. Postcommit controller failure cannot relabel committed effects as a no-effect failure.

`exclusion_contracts` exercises the typed writer in owned isolated PostgreSQL, including identical-command occurrences, historical references, retained archive/evidence, exclusion across source changes and restart, zero-admission replay, stale preview refusal, explicit replay restoration, later normal acquisition, finalized retry/conflict and permanent-removal refusal controls. Controlled `purge`/`excise` rows are fixture inputs, not public implementations. This is distinct from packaged daemon/API/CLI and kill/reply-loss qualification, which remains an integration gate. Existing schema bootstrap still requires a fresh compatible foundation catalog and refuses incompatible predecessor fingerprints; no migration or reset is supplied. This advances slice 1a and does not close full M1, operational/private-corpus acceptance or the final action/library implementation.

`exclusion_package_acceptance -- --package-pin /absolute/package-pin.json` runs the connected packaged qualification without rebuilding the package or compiling the runtime. The pin must record a successful clean build, the exact current commit/tree, one immutable `/nix/store` package and the actual paths/SHA256 of both entrypoints. Mismatches refuse before daemon/database launch, with no fallback to development binaries. This selector cannot combine with other scenario selectors; existing suites retain their original build behavior. The independent mock-response scenario preserves a valid response control while refusing wrong/missing action, method and target bindings. Real daemon/API/CLI scenarios separately exercise selected occurrence removal, retained evidence, source changes, restart, unavailable-provider undo/replay, later acquisition, observed staged/committed kills, pending-projection refusal and a killed CLI after the commit rendezvous. Preparation of these controls alone is not a passing receipt.
