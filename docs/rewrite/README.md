# Foundation contract and source disposition

This candidate prepares the fresh Rust source tree in the existing Sinex repository. It is not a deployed release. The design basis is the Polylogue/Sinex specification revision `0740d4190ffae435c240ed822f2cab84d3cda913`: Sinex purpose/model/storage/surfaces, schema decision, workspace plan and the joint bootstrap inventory. This document records the implemented subset; the broader design remains unimplemented until its own acceptance.

The predecessor tracked source tree at `c997df89764aa47d624355ae04fbe65e6f9a2bfa` is replaced only in this worktree. LICENSE, .gitattributes, .editorconfig, rustfmt.toml, the existing nixpkgs pin (with obsolete lock inputs removed) and all predecessor .beads routing/configuration documents are retained. Task routing stays bound to its existing owner until a separately authorized transition. All predecessor source crates, xtask, examples, CI, hooks, NixOS modules, schemas, cached product declarations and architecture prose are removed from the target tree. Their history remains in Git and the externally preserved pre-rewrite recovery baseline. This is an explicit whole-tree disposition; no directory name was treated as proof that its contents lacked value. No external task database, deployment input, live capture or service state was changed.

Supported foundation: query-free canonical schema control; real reader/writer database permissions; writer connection owned by a bounded admission task; config validation/schema export, status/version/catalog through actual daemon and CLI; controlled startup/shutdown. Synthetic admission is exercised by an internal integration test, not exposed as a public source or RPC.

Atuin, MCP, capture, replay, confirmed delivery, analytics, sealed lifecycle and the native library are not advertised as supported. Composition outlines are not registered capabilities. The minimum bootstrap inventory and all M1 obligations remain open wherever actual tests have not established them.

The event-storage boundary includes the full event-row column shape and structural constraints in `core.events` and `reflection.events`, real UUIDv7 Timescale hypertables, explicit compression/sparse-index settings, occurrence side tables and logical archive topology. The synthetic writer maintains its coordinate and material-count rows in the same transaction. Unknown time stays unknown; known source times and producer clocks retain their declared semantics. Definition checks compare actual indexes, triggers, functions, views and Timescale settings against the protected catalog captured while applying the Rust declarations.

This is not a complete target schema or general admission engine. Material/revision and derivation registries, registered payload validation, full grants/privacy lifecycle, ordered schema changes and remaining target packages still need implementation. Earlier preparation-schema fingerprints are refused, not silently upgraded or reset. Direct schema tests of derived rows, archiving and compression prove that storage boundary; they do not register those operations as supported API routes. `TsOrig` still needs an explicit producer-clock input before general external admission is supported; the current synthetic route emits only Unknown and cannot silently relabel a producer clock.

Shared content storage follows the reviewed hashed-blobs implementation plus the canonical Polylogue owner adaptation adding a non-mutating Reader capability. The adapted code and tests are digest-identical across both preparation trees, not a Sinex implementation fork. Its owner-release pin and cross-consumer release qualification remain open before publication. No private absolute source path or fabricated remote tag is a product dependency.
