# Native dependency boundaries

`xtask boundaries [workspace]` obtains Cargo metadata with all workspace features and the lockfile held fixed. It checks the six implemented packages against the allowed internal edges in the specification workspace plan. Model and xtask have no product dependencies; protocol and store may depend on model; daemon may depend on model, protocol and store; client may depend on model and protocol. A new workspace package requires an explicit policy assignment. Unimplemented target crates are not required stubs.

Every declared dependency is checked by its package name, including renamed, optional, development, build and target-specific dependencies. There is no test harness feature or product-to-xtask dependency in this subset. Pure model/protocol reject runtime, database, TLS, cipher and logging framework dependencies. Their resolved normal/build graph is traversed to catch transitive wrappers; development fixture helpers do not become contract runtime edges. This enforces dependency isolation, not the absence of every possible I/O expression in Rust source.

Canonical PostgreSQL queries and SQLx macros belong to store. The current daemon also owns read-only Atuin SQLite acquisition because the separate sources crate is not implemented. Its SQLx declaration must disable defaults and request only `sqlite` and `runtime-tokio`. The checker examines the daemon's requested features separately from Cargo's resolved feature union: the store legitimately enables PostgreSQL and macros on the same SQLx version. Moving provider acquisition to its target package will require updating this bounded seam with the caller. No other current package may depend directly on SQLx or its component crates. This graph check does not parse SQL source text or prove database role grants.

The normal xtask build/test/check routes run the check before Cargo compilation. Packaging runs it before PostgreSQL bootstrap, and publication runs it in the pre-push hook. Run `agentctl job start /absolute/checkout dependency_boundaries --workspace /absolute/checkout` for the focused qualification without PostgreSQL. Its disposable copy uses the actual workspace manifests and real Cargo resolution, records stdout, stderr and exit statuses, and requires the forbidden-edge controls to fail through the same command that accepts the unchanged native graph.


Build/test/check operate on the workspace selected by the current directory and its Cargo configuration. They refuse `--manifest-path`, `--config`, `--lockfile-path` (separate and equals forms), and Cargo's `-C` directory override before metadata or compilation. To check another workspace, invoke its frontend from that workspace. Package/exclude and target selection remain ordinary Cargo arguments; metadata deliberately checks every workspace package and target declaration. Explicit `--features`/`-F` requests also reach metadata in addition to `--all-features`, including dependency feature requests that workspace features might not enable. Arguments after `--` belong to the test executable and are left to Cargo.


`dependency_routing_control` runs the same narrow driver and additionally requires the explicit path to a preserved pre-fix xtask executable. It reproduces the original alternate-manifest bypass against a copied actual forbidden graph before requiring the corrected frontend to refuse the routing options. This optional regression reproduction never selects an installed executable implicitly.
