# Polylogue material protocol boundary

`integration.polylogue` has seven anchored observation event types: `session`, `lineage`, `usage`, `message`, `block`, `attachment`, and `session_event`. Their schemas live in `schemas/v1/integration.polylogue/` and the registry lists all seven. There is no `session_indexed` event in this contract.

The current reader accepts `polylogue.material-protocol/v1`, semantics version 8, canonicalizer version 2, and Origin vocabulary versions 3 and 4 with their frozen digests. It verifies the manifest, every declared segment's original SHA-256 and size, the joined revision digest, both sequence spaces, record counts, anchors, and session and message closure. The seven record kinds have fixed supported fields and types; optional fields preserve their declared nullability. Every record belongs to the manifest session, and blocks, attachments, and linked session events require an earlier message owner. Unknown versions and undeclared or missing segments fail verification. The public synthetic fixture under `tests/fixtures/polylogue/v1/small-session/` is copied byte for byte from Polylogue's material-protocol fixture; the Rust test resolves every anchor against it.

The Origin version/digest is an append-only compatibility pair. A new producer Origin requires a new frozen producer vocabulary entry and an explicitly added reader pair; changing the v3 digest would invalidate historical material identity. The current v4 pair adds `otel-genai`; the frozen v3 pair remains accepted without changing its digest. Older semantics or canonicalizer versions are rejected rather than silently rehashed.

A segment's original bytes are the retained material. `PolylogueResolvedRecord::original_bytes` and `original_sha256` identify the exact NDJSON line without its terminating LF. `canonical_bytes` and the manifest anchor SHA-256 identify the exact-value sorted-key record under canonicalizer v2. They can differ in JSON framing while both digests remain valid. Unicode normalization is limited to prose fields in the producer record builder; opaque keys and values remain exact. The reader rejects duplicate JSON member names without folding distinct Unicode-equivalent keys before decoding into a map. It also rejects unsupported numeric ranges and sequence overflow. A normalized record is Polylogue's interpretation of source material, not an independently observed provider fact. Exact provider and attachment artifacts need their own registered material roots.

Producers stage and finalize material before publishing `EventIntent` children. A Polylogue intent carries `polylogue_revision`: a registered manifest material ID, a segment-index-to-registered-material-ID map, and separately acquired original witnesses with their normalizer version. Event-engine admission resolves completed blob-backed materials through the native CAS, verifies the manifest against their bytes, and checks every child's claim, event type, material ID, and byte anchor before persistence. Missing registrations or unreadable files keep the raw message unsettled for redelivery; contradictory proofs become ordinary admission rejections and durable DLQ outcomes. Direct Polylogue event admission without revision evidence is rejected. The event payload contains identity and anchor coordinates, not transcript content. Existing durable emission receipts govern producer progress, and the existing raw-message settlement path governs each bounded physical envelope containing a prepared subset of those children. The manifest reconciles members and digests; it does not finalize the envelope or advance a source cursor.


## Local publication and request recovery

Authenticated write callers use `polylogue.revision.publish` with a request ID, normalizer version, exact manifest/segment descriptors, and acquired original descriptors. Each descriptor carries a local readable file locator, SHA-256 and size; originals additionally carry role, Source-owned reference, media type and acquisition coordinates. This is a local/shared-filesystem custody boundary, not a remote upload protocol. The service UID must be able to read the producer's staging files. Installed staging permissions and mTLS readiness require separate operational qualification.

The operations repository serializes preparation by operation/operator/request and persists random material and child IDs before side effects. The shared native splitter preserves the complete proof header and assigns exact bounded partitions. Their fixed header and ordered ranges are committed in the existing operations log before any publish. Each partition PubAck is committed separately; a restart resumes its owed suffix with the same plan and IDs. The fingerprint binds all immutable descriptors, including original order, acquisition and normalizer, while excluding mutable locators. Identical retries reuse those coordinates; a changed fingerprint under the same scope is refused. Incomplete custody can use refreshed same-byte locators. Completed custody is verified from registered CAS and never requires the old locator. Registry identity uses the existing typed `SourceIdentifier` with the prepared material UUID; the transport path remains origin metadata, so distinct requests can reuse a path without aliasing older material.

Acquisition describes exactly the retained selected bytes: `full_snapshot`, `byte_window`, `logical_snapshot` or `unknown`. A full snapshot does not claim an entire physical provider file. Byte windows require nonnegative inclusive-start/exclusive-end coordinates matching retained size, including an empty window. Logical table scope comes from the actual retained export. Unknown extent is preserved. The existing manifest `content_digest.provider_digest` contains `polylogue.original-materials/v1:sha256:<digest>` over the exact ordered original descriptors and normalizer under canonicalizer2; transport paths and material UUIDs are excluded. Normalized revision and segment identities are unchanged.

Native ingestion securely copies transport files to process-owned temporary files and reuses existing CAS leases, byte verification and registration. Generic `ingest_file` retains its root-containment rule. Streaming copy and SHA checks use bounded buffers; native BLAKE3 hashing retains the configured artifact-size limit and currently reads the bounded artifact into memory (512MiB by default). Manifest reads obey that same limit. Segment verification retains record metadata plus record-sized buffers.

`polylogue.revision.status` reads the durable request and native authorities. Until every prepared partition has a recorded PubAck, state is null/pending. `raw_accepted` means JetStream accepted all physical envelopes; it does not unlock producer progress. `persisted_confirmed` additionally requires all exact child event rows and the explicitly configured raw owner's ACK floor to cover every recorded physical sequence. Durable child DLQ witnesses yield `durable_debt` under that same settlement proof. Missing consumer/receipt evidence remains pending, never a timeout-derived failure. The operations log's successful publication records PubAck, independently of child settlement. No second child finalizer is introduced.

Set `SINEX_POLYLOGUE_PYTHON` and `SINEX_POLYLOGUE_CHECKOUT` to the producer environment and clean commit pinned by the external harness before starting a declared gate that executes it. AgentCTL inherits these variables and optional `CARGO_BUILD_JOBS`; leaving the compiler variable unset retains Cargo's configured default.

The external producer proof uses an exact clean Polylogue checkout and its real Source intake/outbox/HTTP transport. It is an explicit heavy test requiring the producer Python environment and checkout, with synthetic TLS/token fixtures. It withholds the raw consumer until staging locators retire, loses a successful native response at a fixture proxy, kills/restarts the API process, then checks CAS, admission, authenticated query, status and the same Source obligation's redrive. Installed-runtime acceptance is separate.

Publication request locks use a separate bounded database pool, split with content and PKM pools from the gateway connection budget. Advisory-lock waiters cannot occupy CAS staging connections; the total allocation remains part of RPC capacity accounting.

A lost publication receipt can leave acceptance indeterminate across PostgreSQL and JetStream. The prepared request retains its interpretation IDs; a retry may create another physical envelope after JetStream's duplicate window expires. Native same-ID redelivery is handled by the existing event writer, and a persisted child row takes precedence over a duplicate's DLQ witness. This interface does not promise exactly-once physical publication across the two stores.

For the single external harness, `SINEX_TEST_DB_POOL_SIZE=2` bounds synthetic database clones independently of gateway connections. Its two simultaneous HTTP requests still exercise two request-coordination connections plus independent CAS capacity (`SINEX_API_POOL_MAX_CONNECTIONS=6`). This setting does not change ACK or test deadlines.

The existing native NATS budget is 900KiB per serialized envelope (the server limit is 1MiB). Valid multi-thousand-record revisions use bounded subsets with the same full manifest and original-material proof. An individually oversized proof header or child remains `ResourceExhausted` pending work, with originals retained; byte/hash/schema contradictions remain validation refusals.

Publication preparation and partition receipts are `OutputKind::OperationRecord`
in the existing operations log. The RPC response is an `EphemeralView` over
those operations and native settlement authorities. Admitted seven-kind records
remain `CanonicalEvent` outputs in the event spine; the response introduces no
projection or new canonical-event type. These classifications use
[`sinex_primitives::output_kind`](../../../sinex-primitives/src/output_kind.rs).
