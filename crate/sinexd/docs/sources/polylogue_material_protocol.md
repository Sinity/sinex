# Polylogue material protocol boundary

`integration.polylogue` has seven anchored observation event types: `session`, `lineage`, `usage`, `message`, `block`, `attachment`, and `session_event`. Their schemas live in `schemas/v1/integration.polylogue/` and the registry lists all seven. There is no `session_indexed` event in this contract.

The current reader accepts `polylogue.material-protocol/v1`, semantics version 8, canonicalizer version 2, and Origin vocabulary versions 3 and 4 with their frozen digests. It verifies the manifest, every declared segment's original SHA-256 and size, the joined revision digest, both sequence spaces, record counts, anchors, and session and message closure. The seven record kinds have fixed supported fields and types; optional fields preserve their declared nullability. Every record belongs to the manifest session, and blocks, attachments, and linked session events require an earlier message owner. Unknown versions and undeclared or missing segments fail verification. The public synthetic fixture under `tests/fixtures/polylogue/v1/small-session/` is copied byte for byte from Polylogue's material-protocol fixture; the Rust test resolves every anchor against it.

The Origin version/digest is an append-only compatibility pair. A new producer Origin requires a new frozen producer vocabulary entry and an explicitly added reader pair; changing the v3 digest would invalidate historical material identity. The current v4 pair adds `otel-genai`; the frozen v3 pair remains accepted without changing its digest. Older semantics or canonicalizer versions are rejected rather than silently rehashed.

A segment's original bytes are the retained material. `PolylogueResolvedRecord::original_bytes` and `original_sha256` identify the exact NDJSON line without its terminating LF. `canonical_bytes` and the manifest anchor SHA-256 identify the exact-value sorted-key record under canonicalizer v2. They can differ in JSON framing while both digests remain valid. Unicode normalization is limited to prose fields in the producer record builder; opaque keys and values remain exact. The reader rejects duplicate JSON member names without folding distinct Unicode-equivalent keys before decoding into a map. It also rejects unsupported numeric ranges and sequence overflow. A normalized record is Polylogue's interpretation of source material, not an independently observed provider fact. Exact provider and attachment artifacts need their own registered material roots.

Producers stage and finalize material before publishing `EventIntent` children. A Polylogue intent carries `polylogue_revision`: the exact manifest JSON and a segment-index-to-registered-material-ID map. Event-engine admission resolves completed materials with a blob reference through the native content store; it never falls back to their mutable staging locator. File-only registrations retain their declared file authority. Verification streams each segment once, retaining record metadata and a record-sized buffer rather than the full revision. It verifies the manifest against those bytes, and checks every child's claim, event type, material ID, and byte anchor before persistence. Missing registrations or unreadable files keep the raw message unsettled for redelivery; contradictory proofs become ordinary admission rejections and durable DLQ outcomes. Direct Polylogue event admission without revision evidence is rejected. The event payload contains identity and anchor coordinates, not transcript content. Existing durable emission receipts govern producer progress, and the existing raw-message settlement path governs the one physical envelope containing those children. The manifest reconciles members and digests; it does not finalize the envelope or advance a source cursor.
